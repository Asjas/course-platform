# Lesson Transcript Implementation Blueprint

## Overview

This blueprint defines how to add robust transcript support for lessons,
including:

- **VTT ingestion** (including tracks fetched from YouTube).
- **Two learner views**:
  - timestamped interactive cues.
  - plain paragraph transcript with no timestamps.
- **Admin operations** for sync, source tracking, and rollback.
- **Publish gating** so lessons with video require valid transcript data.

The plan is optimized for the existing course editor and lesson route in this
repo.

## Locked Decisions

- [x] **Input format**: VTT is the primary transcript input.
- [x] **Source priority**: prefer manual caption track, then auto-generated.
- [x] **Admin metadata**: show source badge (`Manual` or `Auto`) and last
      fetched timestamp.
- [x] **Dual learner modes**:
  - [x] timestamp mode with cue click-to-seek.
  - [x] plain paragraph mode with no timestamps.
- [x] **Timestamp mode UX**:
  - [x] active cue highlight.
  - [x] auto-scroll.
  - [x] `Follow playback` toggle to disable auto-scroll.
- [x] **Paragraph chunking rules**:
  - [x] split on speaker change.
  - [x] split on pause gap > 2.5 seconds.
  - [x] split when paragraph reaches ~500-700 chars.
  - [x] optional speaker labels.
- [x] **Search behavior**:
  - [x] one search index over cues.
  - [x] same match logic in both modes.
  - [x] in paragraph mode, selecting a match seeks to first backing cue.
  - [x] include next/previous controls and keyboard shortcuts.
- [x] **Validation policy**:
  - [x] allow draft save.
  - [x] block publish for invalid transcript when lesson has video.
  - [x] apply same requirement for preview lessons.
- [x] **Sync policy**:
  - [x] manual re-sync from admin.
  - [x] scheduled refresh only for auto tracks (daily for 7 days after upload).
  - [x] never overwrite manual selection without explicit confirmation.
  - [x] keep transcript version history and allow rollback.

## Data Model Plan

### Current State

`course_lesson.transcription` already exists as required JSON.

### Target Shape

- [x] Define a strict transcription schema in TypeScript (frontend + backend).
- [x] Store normalized cue-based structure (single source of truth).
- [x] Keep enough metadata for auditing and sync decisions.

Suggested payload shape:

```json
{
  "version": 1,
  "language": "en",
  "source": "manual",
  "sourceProvider": "youtube",
  "sourceTrackId": "yt-caption-track-id",
  "lastFetchedAt": "2026-04-03T12:34:56.000Z",
  "isAutoGenerated": false,
  "cueCount": 123,
  "durationMs": 1805230,
  "cues": [
    {
      "id": "c1",
      "startMs": 11000,
      "endMs": 13000,
      "text": "Welcome to the lesson.",
      "speaker": "Instructor"
    }
  ]
}
```

Version history strategy:

- [ ] Add a transcript history store (new table or append-only JSON snapshots).
- [ ] Save previous snapshot before any re-sync overwrite.
- [ ] Include actor and timestamp for rollback auditing.

## Risks and Mitigations

- [ ] **YouTube caption availability lag** after upload.
  - Mitigation: retries + scheduled refresh window.
- [ ] **Auto caption quality variance**.
  - Mitigation: manual priority + admin re-sync + rollback.
- [ ] **Large transcript performance issues**.
  - Mitigation: memoized derivations + optional list virtualization.
- [ ] **Schema drift in historical transcript JSON**.
  - Mitigation: versioned payload + migration guard logic.
